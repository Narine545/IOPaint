# Что не так с IOPaint сегодня и что с этим делать

Это разбор состояния апстрима (`Sanster/IOPaint`, последний релиз 1.6.0) с
точки зрения человека, который хочет пользоваться им как рабочим инструментом
на обычном ПК без NVIDIA. Часть проблем уже исправлена в этом форке — они
помечены **[сделано]**, остальное — предложения на будущее.

---

## 1. Зависимости: всё было заморожено на начало 2024 года **[сделано]**

В `requirements.txt` стояли жёсткие пины:
`diffusers==0.27.2`, `huggingface_hub==0.25.2`, `Pillow==9.5.0`,
`peft==0.7.1`, `gradio==4.21.0`, `fastapi==0.108.0`, `controlnet-aux==0.0.3`.

Чем это плохо: пакет невозможно поставить рядом с чем-то современным, а
`Pillow==9.5.0` вообще не собирается/не ставится на Python 3.12+ и тянет за
собой известные уязвимости.

Что сделано:

* пины заменены на диапазоны, где это безопасно;
* зависимости разделены на **core** (`requirements.txt`) и экстры
  `diffusion` / `plugins` / `webconfig`;
* `Pillow==9.5.0` был нужен из-за одного вызова `font.getsize()` в AnyText —
  переписано на `font.getbbox()`, пин снят;
* `imghdr` (удалён в Python 3.13) заменён на собственное определение формата
  по сигнатуре файла;
* `@model_validator(mode="after")` переписан под Pydantic 2.12+.

Проверено вживую на стеке: torch 2.14, Pillow 12, huggingface_hub 2.0,
fastapi 0.141, pydantic 2.13, rembg 2.0.85, onnxruntime 1.30 — работает.

## 2. Нельзя было установить «лёгкую» версию **[сделано]**

`iopaint/model/__init__.py` импортировал *все* модели сразу, включая
диффузионные, а `iopaint/model/utils.py` тянул `diffusers` на уровне модуля.
Итог: чтобы стереть объект моделью LaMa (200 МБ), нужно было поставить
`diffusers` + `transformers` + `peft` + `accelerate` — это ~3–5 ГБ.

Сделано: реестр моделей стал ленивым (`_ModelRegistry`), `diffusers`
импортируется только при реальном обращении к диффузионной модели. Теперь
`pip install ".[plugins]"` даёт полностью рабочий стиратель + удаление фона
без диффузии, а `pip install ".[diffusion]"` доустанавливает остальное.

## 3. Плагин RemoveBG использовал модели вполсилы **[сделано]**

* Никакого альфа-маттинга: возвращалась «сырая» бинарная маска модели —
  отсюда рваные волосы и белая кайма на светлом фоне.
* `rembg.new_session()` вызывался без `providers`, то есть даже при наличии
  GPU-провайдера onnxruntime всё считалось на CPU.
* Композит делался тремя разными способами в трёх ветках кода
  (briaai / rembg / anime_seg) — разное поведение для разных моделей.

Сделано: единый конвейер `модель → альфа → (маттинг) → удаление подмеса
фона → RGBA`, общий для RemoveBG и AnimeSeg; провайдеры onnxruntime
настраиваются; параметры доступны из CLI, API и UI.

## 4. Не было настройки CPU **[сделано]**

PyTorch по умолчанию берёт все логические потоки (16 на Ryzen 7 5700G).
Для свёрточных сетей это стабильно медленнее, чем по числу физических ядер
(8), из-за конкуренции SMT-потоков за исполнительные блоки. Добавлен
`--cpu-threads` (0 = автоопределение физических ядер), `set_num_interop_threads(1)`,
`OMP_WAIT_POLICY=PASSIVE`, `cv2.setNumThreads`.

## 5. Репозиторий нельзя «склонировать и запустить» **[сделано]**

Собранный фронтенд (`iopaint/web_app`) был в `.gitignore`, то есть после
`git clone` сервер падал на монтировании статики, и требовался Node.js.
Теперь `dist` закоммичен (3 МБ), а `publish.sh` его пересобирает.
Плюс добавлены `.bat`-скрипты установки/запуска для Windows.

## 6. Тестов, которые можно запустить, фактически не было **[частично]**

Все тесты в `iopaint/tests` требуют скачивания весов (сотни МБ) и часто GPU,
поэтому в CI их никто не гонял (workflow'ов в репозитории вообще нет).
Добавлено 20 быстрых тестов без моделей (альфа-маттинг, конвейер плагина,
подмена предиктора) и GitHub Actions на Python 3.10–3.12.

## Что стоит сделать дальше (в порядке пользы для вашего железа)

1. **LaMa → ONNX.** Самый большой потенциальный выигрыш: ONNX-версия LaMa
   через `onnxruntime-directml` реально считается на Radeon Vega, тогда как
   torch-DirectML для неё нестабилен. Ожидаемо 2–4× к скорости стирания.
2. **Тайлинг для удаления фона.** Сейчас модель resize'ит вход до 1024×1024,
   поэтому на 12 Мп фото край получается «мягким». Тайловый проход по
   изображению в 2–4 тайла даст заметно более точную маску на волосах.
3. **Кэш сессий rembg.** При переключении модели старая сессия выбрасывается;
   держать 2–3 в памяти (они по 40–180 МБ) — быстрее для рабочего процесса
   «фото → аниме → фото».
4. **Портативная сборка.** Windows embeddable Python + предзагруженные модели
   в один ZIP: запуск вообще без установки Python. Можно собрать по образцу
   `scripts/pack.bat`, но с CPU-колёсами.
5. **Фронтенд.** В `package.json` одновременно `recoil` (проект заморожен
   Meta в 2024) и `zustand`; стоит выкинуть recoil и обновить vite 5 → 7.
6. **Ruff + pre-commit + pip-audit** в CI: кода много, стиль разъезжается.
7. **Апстрим.** Изменения из пунктов 1–5 этого списка имеет смысл предложить
   в `Sanster/IOPaint` отдельными PR — альфа-маттинг и ленивые импорты
   полезны всем, а не только вам.

## Честно о том, чего ждать не стоит

* **Диффузионные модели (SD/SDXL/PowerPaint) на вашем железе** — это минуты
  на одну генерацию 512×512 и 8–12 ГБ RAM. Они установлены отдельным
  скриптом не просто так: для замены объектов на CPU это скорее «посмотреть,
  как работает», чем рабочий инструмент.
* **2 ГБ видеопамяти iGPU** — это потолок для ONNX-моделей среднего размера.
  BiRefNet и SAM2-large туда не влезут, а `isnet`/`u2net` влезут.
* **Альфа-маттинг не чинит плохую маску.** Если модель не нашла объект,
  маттинг только сгладит ошибку. Для сложных случаев быстрее выделить объект
  плагином Interactive Segmentation (SAM2) и доработать кистью.
